## P0 — 한글 입력·렌더링을 제품 기본 품질로 복구

### 사용자 확인 문제

Unclecode의 한글 지원이 여전히 불안정하다. 첨부 화면처럼 한글 음절 사이가 과도하게 벌어져 보이거나 줄바꿈·정렬이 자연스럽지 않고, 실제 한국어 사용자에게 메인 입력/대화 화면의 기본 사용성이 깨져 있다. 이를 폰트 취향 문제가 아니라 **Unicode 폭 계산, IME 입력, 커서 및 줄바꿈 전반의 P0 제품 결함**으로 취급한다.

### 작업

#### 1. 한글 표시 폭과 줄바꿈

- [ ] 한글 완성형 음절, 자모, 호환 자모의 터미널 cell width 계산을 실제 렌더러와 일치시킴.
- [ ] 한글 음절 사이에 의도하지 않은 공백이 들어가거나 글자가 한 칸씩 과도하게 벌어지는 원인을 확인.
- [ ] 한글+영문+숫자+기호가 섞인 문장에서 wrap 지점과 화면 정렬이 깨지지 않게 함.
- [ ] 굵게, dim, 색상 ANSI 스타일이 섞여도 표시 폭 계산에서 escape sequence를 제외.
- [ ] 긴 한글 사용자 메시지, 어시스턴트 답변, 툴 결과가 화면 폭에 맞게 자연스럽게 줄바꿈되게 함.
- [ ] 창 크기 변경 후 한글 행이 겹치거나 잘리거나 잔상이 남지 않게 함.

#### 2. IME 조합 입력

- [ ] macOS 한글 IME의 조합 중 텍스트와 확정 텍스트를 구분해 중복 입력을 방지.
- [ ] 조합 중 Enter, Backspace, 방향키, Esc가 글자를 분해하거나 중복 확정하지 않게 함.
- [ ] 빠르게 입력할 때 초성·중성·종성이 유실되거나 순서가 바뀌지 않게 함.
- [ ] 영문↔한글 입력기 전환 직후 첫 글자가 누락되지 않게 함.
- [ ] 한글 조합 중 slash picker, 승인 카드, overlay 단축키가 오작동하지 않게 함.

#### 3. 커서·편집 동작

- [ ] 좌우 방향키가 UTF-16/code point가 아니라 grapheme cluster 단위로 이동.
- [ ] Backspace/Delete가 완성형 음절, 조합 중 음절, 이모지 결합 문자를 안전하게 삭제.
- [ ] 한글 문장 중간 삽입 시 커서의 논리 위치와 화면 cell 위치가 일치.
- [ ] Home/End, 단어 단위 이동, multiline composer에서 한글 기준 이동을 검증.
- [ ] 붙여넣기한 한글이 깨지거나 여러 번 입력되지 않게 bracketed paste 경로를 검증.

#### 4. 검색·저장·재개

- [ ] 한글 프롬프트가 세션 저장/재개 후 원문 그대로 유지.
- [ ] 한글 파일명과 경로를 read/write/search 도구에서 정상 처리.
- [ ] `/context`, 세션 검색, TODO 및 transcript 필터에서 한글 검색이 정상 동작.
- [ ] NFC/NFD가 섞이는 macOS 파일명과 입력 문자열의 비교 정책을 명확히 함.

### 검증

- [ ] `안녕하세요`, `한글English123`, 자모 문자열, emoji+한글 혼합의 width/wrap 골든 테스트.
- [ ] 한글 한 줄·여러 줄 입력의 커서 이동, 삽입, Backspace/Delete 테스트.
- [ ] IME 조합 이벤트 시뮬레이션 또는 PTY 기반 입력 테스트.
- [ ] 좁은 폭과 넓은 폭에서 동일 문장의 줄바꿈 및 레이아웃 스냅샷 테스트.
- [ ] 한글 사용자/assistant/tool 블록이 섞인 긴 대화의 tmux 런타임 스모크.
- [ ] macOS 기본 터미널, iTerm2 등 최소 2개 실제 터미널에서 수동 검증.
- [ ] 스크롤 핫픽스와 결합 검증: 긴 한글 대화를 위로 스크롤해도 행 계산과 위치가 정확해야 함.

## 완료 기준

1. 한글 음절 사이에 비정상적인 간격이 생기지 않는다.
2. 한글 IME 조합·확정·삭제·커서 이동이 일반 편집기처럼 동작한다.
3. 한글과 영문이 섞인 긴 문장이 정확하게 줄바꿈되고 리사이즈 후에도 깨지지 않는다.
4. 저장·재개·검색·파일 경로에서 한글 원문이 보존된다.
5. 자동화 테스트와 실제 macOS 터미널 검증이 모두 통과한다.
